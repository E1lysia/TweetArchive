# 已下载图片的推文归档

沿用现有 gallery-dl 和 `cookies.txt`，只获取已下载图片对应的推文原文，并展示已经保存的中文译文。配置 DeepL API 后，会自动批量补译缺失的正文；本脚本不下载新图片。

## 使用

双击 `推文归档.cmd`，默认核对账号表中的全部账号；完成后双击 `推文归档.html` 离线阅读。可按作者、月份、状态和文字搜索，支持“双语对照／仅中文／仅原文”切换，也能用中文搜索译文。

原来的 `补新.cmd` 现在会在下载媒体后自动归档推文并补译。只想关联已有图片时，可单独运行 `推文归档.cmd`；只想补译已有正文时，运行 `补译中文.cmd`。首次配置请看 [DeepL使用说明.md](DeepL使用说明.md)。

只处理一个账号：

```bat
推文归档.cmd --index 1
```

只核对少量记录（试运行）：

```bat
推文归档.cmd --index 1 --limit 5
```

不联网，仅重新扫描本地图片并生成浏览页：

```bat
推文归档.cmd --offline
```

## 保存位置

- 原图片与下载去重库保持原状。
- 每个账号目录的 `推文/年/月/推文ID.json`：原文、北京时间、原帖链接、抓取元数据和本地图片路径。
- 同位置的 `.md`：可直接阅读的原文与图片链接。
- `_推文归档/tweets.sqlite`：独立的推文库；按账号和推文 ID 去重。
- 根目录 `推文归档.html`：内嵌推文数据的离线浏览页；`_推文归档/data.js` 为数据导出副本。浏览时不请求远程图片和接口；点击“查看原推”才打开 X。
- `_推文归档/gallery-cache.sqlite`：gallery-dl 抓取缓存。

## 范围与状态

只匹配现有日期_推文ID_序号格式的 JPG、PNG、WebP 图片。视频、GIF、缩略图总览和纯文字推文不在本次归档范围。

在线核对后，只归档目标账号的原创推文；转推、展开的引用原帖，以及引用其他推文的帖子均排除。排除只影响推文库及浏览页，不删除原有图片。

**已取得原文**表示已获取推文元数据并核对原创身份。**正文待补全**表示只有本地图片，尚未取得或核实原文，不应当成已确认原创记录；浏览页可筛选“已取得原文”。待补全记录的时间由推文 ID 推算。

首次批量抓取使用账号的 `/media` 时间线，不保证能恢复已删除、设为不可见或平台不再返回的推文。之后只处理新增图片和正文待补全记录：不超过 20 条时直接读取单条推文，较多时扫描媒体时间线。已核对的推文自动跳过，不重复创建文档；没有待补全记录时不联网。

中断或失败会保留已经保存的原文，并重新生成浏览页；未成功取得的不会写入虚构正文。

## 中文译文

2026年10月29日为现有归档补充了 Codex 生成的简体中文译文，保留作品名、原始链接与话题标签。译文同时保存在 SQLite、每条推文的 JSON、Markdown 和离线浏览页中；无文字的推文显示“原推无文字正文，无需翻译”。表情、链接或标签没有可翻译文字时按原样保留。

译文导出文件保存在 `_推文归档/translations.zh-CN.json`，按原文的 SHA-256 校验关联，不会错配到其他正文。再次导入相同译文会自动跳过：

```bat
推文归档.cmd --import-translations "D:\gallery-dl\_推文归档\translations.zh-CN.json"
```

日常补新和重建页面会保留已有译文；若之后获取到的原文内容发生变化，旧译文将失效，避免继续展示不对应的翻译。新增正文在配置 DeepL 后会自动翻译；未填密钥、额度不足或翻译失败时，原文先保存，页面显示“中文译文待补充”，可稍后运行 `补译中文.cmd` 继续。不会向翻译服务发送图片或登录 cookie。

## 备份

备份整个 `D:\gallery-dl` 可保留图片、原文和相对路径。`cookies.txt` 是登录凭据，请不要分享；推文 JSON 和浏览页不包含 cookie。
